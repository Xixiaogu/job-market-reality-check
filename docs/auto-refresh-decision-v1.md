# 岗位采集后的自动刷新与投递决策重算

## 目标

当浏览器扩展新增或更新岗位后：

1. 岗位管理页面自动刷新岗位总数和列表；
2. 投递决策页面自动重新计算并刷新分组、分数和岗位卡片；
3. 分析管线完成后，市场分析看板自动载入新生成结果；
4. “重新计算”按钮直接使用同一次计算返回的汇总、岗位列表和校准结果，不再计算后又读取到旧页面状态。

## 实现

- 岗位管理和投递决策每 2 秒读取一次 `/api/v1/health` 的 `job_count`。
- 检测到岗位数量变化时，只刷新当前页面的数据，不打开新窗口。
- 投递决策的重算接口返回一个原子结果包：
  - `summary`
  - `jobs`
  - `calibration`
  - 顶层运行信息与 `run_id`
- 市场看板继续轮询分析管线。发现比当前页面更新的成功运行后，保存滚动位置并自动重新载入。
- 页面处于后台标签时不执行自动刷新；重新切回页面会立即检查一次。

## 手工验收

1. 同时打开岗位管理、投递决策和市场分析。
2. 浏览器扩展采集一个全新岗位。
3. 岗位管理应在约 2 秒内自动出现新岗位。
4. 投递决策应在约 2 秒内显示“检测到岗位库变化”，并更新运行编号和岗位数量。
5. 等待扩展触发的分析管线完成；市场分析应自动重新载入新结果。
6. 再点击“重新计算”，页面应出现“重新计算完成：N个岗位 · 运行 #X”，且运行编号递增。
